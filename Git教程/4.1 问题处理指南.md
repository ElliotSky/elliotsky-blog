### 坑1：提交代码Github不显示贡献绿点

原因：当前仓库user.email 和Github绑定邮箱不一致

解决：`git config user.email` 核对邮箱，修改为平台绑定邮箱即可。

### 坑2：修改全局配置，旧仓库不生效

原因：旧仓库已经存在local本地配置，优先级高于global全局配置

解决：进入项目执行 `git config --local --unset user.email` 删除本地配置，复用全局配置。

### 坑3：换行符频繁变更，代码全红

原因：未配置core.autocrlf，跨系统换行符不统一

解决：按照系统执行上文换行符配置即可。

### 坑4：macOS专属报错：git\@github.com: Permission denied (publickey)

**报错含义**：SSH公钥校验失败、密钥未托管、git邮箱与ssh密钥邮箱不匹配、本机ssh配置受限，是macOS新版系统最高频Git报错，适配 Ventura/Sonoma/Sequoia 全版本

### 坑5：HTTPS 推送/拉取报 TLS 握手失败或连接重置
**原因**：网络抖动、代理配置错误（如开了代理但 Git 没走代理），或系统自带的 GnuTLS 库存在兼容性问题。
**解决**：先重试；若使用代理，需配置 `git config --global http.proxy http://127.0.0.1:端口`；若无效，可尝试强制 Git 使用 TLS 1.2 或切换至 OpenSSL 版本的 Git。

### 坑6：推送大文件或大仓库时 `Broken pipe` / `RPC failed`
**原因**：HTTPS 协议下默认的 POST 缓冲区（`http.postBuffer`）太小，无法承载大包数据，导致连接中断。
**解决**：增大缓冲区，执行 `git config http.postBuffer 524288000`（约 500MB）；若使用 HTTP/2 报错，可尝试降级为 `git config http.version HTTP/1.1`。

### 坑7：`.gitignore` 规则不生效，文件依然被追踪
**原因**：文件在添加忽略规则之前就已经被 Git 纳入了版本管理（tracked），`.gitignore` 对已追踪文件无效。
**解决**：先从缓存中移除追踪（不删本地文件），再提交：`git rm --cached <文件名>`，然后正常提交即可。

### 坑8：仓库体积莫名膨胀，`.git` 文件夹巨大
**原因**：历史提交中误入了大文件（如二进制、数据集），或者因文件权限/换行符频繁变动导致 Git 反复生成新的 Blob 对象。
**解决**：用 `git filter-repo` 重写历史移除大文件（需通知协作者重新克隆）；日常将大文件交给 Git LFS 管理，并关闭不必要的文件模式检测 `git config core.filemode false`。

### 坑9：`git pull` 被拒绝，提示本地修改会被覆盖
**原因**：工作区有未提交的修改，而拉取的内容恰好涉及这些文件，Git 为防止丢失数据拒绝合并。
**解决**：先提交或暂存本地修改（`git stash`），拉取完成后再恢复（`git stash pop`）；或者先提交本地修改再执行 `git pull --rebase`。

### 坑10：长时间分支反复合并后，冲突反复出现且历史混乱
**原因**：对长期存在的分支使用了 **Squash Merge**（压缩合并）。Squash 不产生合并提交，导致 Git 每次合并都回到最初的共同祖先去对比，之前解决过的冲突会再次出现。
**解决**：对于需要反复合并的长生命分支，坚持使用普通合并（`--no-ff`）保留合并提交，让 Git 有新的基准点来缩小对比范围。

### 坑11：已推送的提交包含敏感信息或错误，想撤销却改乱了公共历史
**原因**：直接用 `git reset` 或 `rebase` 修改了已经推送到远程的提交，导致本地与远程分叉，其他人拉取时产生大量冲突。
**解决**：如果提交已公开，优先用 `git revert` 生成一个反向提交来撤销内容，而不是重写历史；若必须重写，需提前通知所有协作者，并使用 `--force-with-lease` 安全强推。

### 坑12：换电脑或重装系统后，`git pull` 一直提示输入密码且认证失败
**原因**：GitHub 已不再支持账户密码进行 Git 操作，必须使用 Personal Access Token（PAT）或 SSH 密钥。
**解决**：在 GitHub 设置中生成 PAT，在提示输入密码时粘贴 Token 代替密码；或者配置 SSH 密钥并切换远程地址为 `git@github.com:...` 格式。

### 坑13：Windows 下克隆后，文件权限或文件名大小写导致诡异问题
**原因**：Windows 文件系统不区分大小写（`file.txt` 与 `File.txt` 被视为同一文件），且默认挂载的权限位与 Linux/macOS 不同，可能导致切换分支时文件残留或权限错乱。
**解决**：在 Windows 上设置 `git config core.ignorecase true`（通常默认开启）；若涉及权限，可设置 `git config core.filemode false` 忽略权限变动。

### 坑14：`git status` 显示大量未修改的文件被标记为已更改
**原因**：通常是换行符（CRLF/LF）自动转换或文件权限模式（filemode）变化引起的，Git 认为文件内容变了，实际是元数据变动。
**解决**：检查 `core.autocrlf` 配置是否统一；执行 `git config core.filemode false` 忽略权限变更，然后 `git reset --hard` 重置工作区。

### 坑15：误操作导致 `index.lock` 文件残留，所有 Git 操作被锁
**原因**：Git 进程意外中断（如强制关闭终端、断网、切换 VPN），留下了锁文件，阻止后续操作。
**解决**：确认没有正在运行的 Git 进程后，手动删除锁文件：`rm -f .git/index.lock`，然后重新执行操作。

### 坑16：本地分支与远程分支名字不匹配，推送时提示无关联
**原因**：本地新建分支后直接 `git push`，Git 不知道该推到远程哪个分支，或远程分支名与本地不同。
**解决**：首次推送时指定关联：`git push -u origin 本地分支名:远程分支名`；后续直接 `git push` 即可。
