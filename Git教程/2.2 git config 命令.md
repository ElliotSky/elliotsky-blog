### 1. 基础内容
#### 1.1 三层作用域
`git config` 划分了三层作用域：
- 系统级：`--system`，作用范围为**本机所有用户和仓库** 
- 全局级：`--global`，作用范围为**当前用户的所有仓库**
- 本地级：`--local`，作用范围为**当前仓库**

**本地级优先级最高，向下逐层覆盖。** 
（优先级：仓库级 > 用户级 > 系统级）

>注：如果不指定作用域，`git config` 默认读写本地级（`.git/config`）。

>注：修改系统级配置通常需要管理员权限。

#### 1.2 最常用的配置命令
首次安装 Git 后必须做配置项：
```
# 配置全局用户名
git config --global user.name "你的名字"

# 配置全局开发者邮箱
git config --global user.email "你的邮箱"
```

查看仓库配置信息：
```
# 查看当前仓库用户名（本地级）
git config user.name

# 查看全局仓库开发者邮箱（全局级）
git config --global user.email

# 列出当前生效的所有配置（含重复项，后出现的会覆盖前面的）
git config --list
```

删除配置项：
```
# 删除全局的代理设置
git config --global --unset http.proxy
```

### 2. 进阶内容
#### 2.1 三层作用域的配置详情文件
每个层作用域的配置详情都在一个文本文件里：
- 系统级：Windows: `C:\ProgramData\Git\config`；Linux/macOS: `/etc/gitconfig`
- 全局级：`~/.gitconfig` 或 `~/.config/git/config`
- 本地级：当前仓库的 `.git/config`

##### 2.1.1 系统级配置文件
展示所有生效的系统级配置项，并展示命令行所在源文件位置：
```
git config --system --list --show-origin
```

**配置详解**
没写的配置项无需关心。

`core.autocrlf=true` 
自动处理win与linux的换行符兼容问题，避免跨平台协作因换行符兼容导致的大量无意义变更。
Windows 使用 `CRLF`，而 Linux/macOS 使用 `LF`，提交时自动将 `CRLF` 转换为 `LF` 存入仓库，在检出代码时再将 `LF` 转换回 `CRLF`。

`pull.rebase=false`
`git pull` 默认采用合并策略，设为ture才采用变基策略。合并提交会保留分叉历史；变基则产生线性历史。

`credential.helper=manager`
指定外部程序来安全地管理远程仓库的认证凭据，避免重复登陆，这里指定了 Windows 的凭据管理器。

`init.defaultbranch=master`
默认分支名 master，可以手动改为 main 与 GitHub 对齐，但这通常通过 `--global` 级别修改即可。

##### 2.1.3 本地级配置文件
展示所有生效的本地级配置项，并展示命令行所在源文件位置：
```
git config --local --list --show-origin
```

**配置详解**
没写的配置项无需关心。

`remote.origin.url=https://github.com/ElliotSky/elliotsky-blog.git`
远程仓库 `origin` 的地址，`origin` 是关联时给远程起的别名，克隆也会默认使用该别名。

`remote.origin.fetch=+refs/heads/*:refs/remotes/origin/*`
- **`remote.origin.fetch`**：定义"`git fetch origin` 时，把远程的**哪些分支**下载到本地的**哪些远程跟踪分支**"。
- `+`：允许强制更新
- `refs/heads/*`：远程仓库里所有分支
	- （`refs/heads/` 是远程分支的命名空间，`*` 匹配任意分支名）
- `refs/remotes/origin/*`：下载到本地后存放为远程跟踪分支
	- （`refs/remotes/origin/` 是本地记录远程分支的命名空间）

`branch.main.remote=origin`
指定本地 `main` 的上游远程分支是 `origin` 这个分支。

`branch.main.merge=refs/heads/main`
- **`branch.main.merge`**：定义"本地 `main` 分支**跟踪**远程的哪个分支"，供 `git pull` / `git status` 使用。
- 本地 `main` 的**上游分支**是远程 `origin` 里的 `refs/heads/main`（即 `main` 分支）
